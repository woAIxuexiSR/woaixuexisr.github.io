    {%- comment -%} Math handling (Requirement 11.2). Decision: do NOT change the global kramdown config; configure MathJax to accept every delimiter form that reaches the HTML. Rationale: kramdown options in Jekyll are GLOBAL — `math_engine` cannot be scoped to just the `notes` collection via front-matter defaults — so setting `math_engine: nil` would also change the chirpy blog's math output, violating the "keep the notes section fully separate from chirpy" requirement (Req 1). What actually reaches the HTML (verified against the sample notes): * Single-dollar inline math `$...$` is NOT recognised by kramdown, so it passes through literally (e.g. `$k$`, `$1\%$`) and MathJax typesets it. * Block `$$...$$` is rewritten by kramdown's mathjax engine into `\[...\]` (and `\(...\)` for the inline `$$` form) — still valid LaTeX delimiters. MathJax below is configured for BOTH `$...$`/`$$...$$` and `\(...\)`/`\[...\]`, so every form renders.
